# cloudflare-worker

Прокси-воркер для бота: `steamcommunity.com` и `csfloat.com`.

Раньше код воркера жил только в дашборде Cloudflare, и это уже стоило времени —
причину ошибки `host not allowed: csfloat.com` нельзя было увидеть, не открыв
дашборд, а комментарии в Python-коде успели разойтись с реальностью. Теперь
исходник здесь.

## Зачем

У Render датацентровый IP. Для **CSFloat** это подтверждённая проблема: площадка
сама отвечает `429` с телом `Please disable your VPN or try a different network`,
то есть режет по адресу. Воркер ходит с edge-IP Cloudflare — это попытка обойти
именно её. Сработает или нет, зависит от того, не в том же ли чёрном списке
адреса Cloudflare; проверяется только опытом.

Для **Steam** воркер не нужен и в боте не используется (`STEAM_PROXY_URL` пуст).
Ранняя версия комментариев утверждала, что он чинил бан по IP — это оказалось
неверно: реальной причиной была бета-версия торговой площадки на аккаунте, а
починила её кука `bMarketOptOut=1`. Steam-ветка оставлена рабочей на случай
надобности, но выдавать её за решённую задачу не надо.

## Для CSFloat воркер обязателен — проверено 2026-08-19

Переменную `CSFLOAT_PROXY_URL` убирали и гоняли `/arbnow` напрямую с Render.
Пришёл `429` с телом `{"error": "Please disable your VPN or try a different
network, too many requests"}` и **без единого заголовка лимита** — то есть бан
по репутации адреса, ровно тот, ради которого воркер и заводился. Через воркер
в ту же минуту запрос доезжает и ключ виден (`x-ratelimit-limit: 200`, аноним
получил бы 50000). Снимать воркер нельзя.

### Ошибочная версия, которую не надо воскрешать

Некоторое время держалось объяснение: «`x-ratelimit-remaining: 0` приходит на
первый же запрос свежего процесса, значит окно привязано к IP, а исходящий
адрес Cloudflare Workers общий на всех арендаторов, и бюджет выжигают чужие».

**Это неверно.** В успешном прогоне счётчик шёл `199 -> 198 -> 197 -> 196` на
наши четыре запроса, то есть убывает ровно на нашу активность: бюджет
привязан к ключу и принадлежит нам целиком. Нулевой остаток был нашей же
работой — 200 запросов в час против прежних 4 страниц каждые 5 минут (48/час)
плюс передеплои, каждый из которых восстанавливал джобы и заново сканировал.
Лечится экономией запросов, а не сменой маршрута.

## Развёртывание

Cloudflare Dashboard → Workers & Pages → `dextrade-steam-proxy` → Edit code →
вставить `worker.js` → Deploy.

## Переменные на стороне бота

| Переменная | Значение |
|---|---|
| `CSFLOAT_PROXY_URL` | `https://<воркер>.workers.dev` |
| `STEAM_PROXY_URL` | то же самое, если понадобится Steam через прокси (сейчас не нужно) |

Бот обращается так: `GET /proxy?url=<целевой URL>`.

## Ручная проверка

```
https://<воркер>.workers.dev/                                   → ok
https://<воркер>.workers.dev/proxy?url=https://csfloat.com/api/v1/listings?limit=1&debug=1
```

`debug=1` возвращает `200` с настоящим статусом, заголовками и началом тела
ответа внутри JSON — так видно, что именно ответил upstream, прямо из браузера.

## Тесты

```
node worker.test.mjs
```

Гоняет логику воркера с подменённым `fetch`: маршрутизация, белый список,
заголовки к каждому upstream, проброс заголовков ответа, `debug=1`.

## Что легко сломать

- **Белый список.** Без него воркер становится открытым прокси на что угодно.
- **Проброс заголовков ответа.** Бот отличает настоящую квоту от блока по IP по
  наличию `Retry-After` и `X-RateLimit-*`. Прежняя версия оставляла только
  `Content-Type`, и любой `429` выглядел бы как блок по IP.
- **`Content-Encoding` в ответе.** Тело читается через `arrayBuffer()`, то есть
  уже распаковано; переслать старый `Content-Encoding` — сломать клиента.
- **`Cookie` к Steam.** Без него не доезжает `bMarketOptOut=1` — ровно та кука,
  которая чинит выдачу JSON вместо страницы бета-маркета.
- **Имитация браузера для CSFloat.** Не добавлять. На проде трижды проверено:
  обрезанный `Mozilla/5.0`, полный набор заголовков Chrome и честный клиент дают
  идентичный `429`. Заголовки там ни на что не влияют.
